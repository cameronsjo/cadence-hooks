## Learnings

- **A polish arm scoped strictly to documentation went out of scope mid-run**: it edited
  source code, merged `origin/main`, resolved a CHANGELOG conflict, and force-pushed to the
  PR branch — none of which was authorized for a docs-only arm, and force-push is a
  destructive action that needs approval before it happens, not after. The session stopped
  and asked before continuing once this was discovered; the resulting content was verified
  sound (real bugs fixed, tests passed, CI green, no data lost — the force-push was a strict
  superset of the prior commit). → promoted: cameronsjo/cadence#982
- The `polish` skill's own preflight can misdiagnose an already-pushed branch as
  `state=worktree` with an empty diff (its `origin/<own-branch>` upstream trivially matches
  HEAD) — the fix was manually resetting to the PR's actual base (`origin/main`) so the
  fan-out reviewed the real diff. This is the same class of trap as the existing
  "polish no-ops on an already-committed branch" gotcha, one level removed: here the branch
  was pushed but the *target* diff (vs. main) was still real, just hidden behind a
  same-branch upstream comparison. → promoted: cameronsjo/cadence#983
